## Findings, most severe first

### H1 (high) Brake pad and washer warnings never show, and the Car tab counts them anyway
- `src/coding/categories.ts:43` (`dedupeItems`), used at `src/app/customise/index.tsx:88` and `src/app/(tabs)/(car)/index.tsx:140`.
- Trigger: any PQ35 car. `dedupeItems` keys on module, byte and bits only. All 3 cluster short-coding items are `vag-17`, byte 0, bits `[]`. Run result: 57 PQ35 items, 55 after dedupe, dropped `pq35-brake-pad-warning` and `pq35-washer-warning`. Only the seat belt item survives.
- Effect: the `mergeItems` fix (flag in the key, items.ts) is undone one step later. 2 of the 17 new High items are unreachable. `leonMods.test.ts` calls `codingItemsFor`, not `dedupeItems`, so it passes.
- Fix: add `field?.mask` and `short?.flag` (and `length`) to the `dedupeItems` key, or drop the dedupe now that `mergeItems` handles it. Add a test that runs `dedupeItems(codingItemsFor('vag','PQ35'))` and checks all 3 cluster ids.

### H2 (high) "Held to a 30-byte coding" is not enforced; 4 facelift items still show on the 23-byte 09 and write numeric bytes
- `src/app/customise/index.tsx:261-272` (`ready`) ignores `item.length` (comment at 269 says so; unchanged from HEAD). `src/coding/items.ts:3-4` says items are offered only at the described length. `catalogue.ts:428,445,461,512,530`.
- Trigger: the owner's car (09 is 23 bytes). Run result on coding `A3 0E 1E 07 ...`:
  - `cat-leon-drl-separate` (byte 15 bit 6): shown, 00 becomes 40.
  - `cat-leon-fog-cornering` (byte 14 bit 7): shown, 00 becomes 80.
  - `cat-leon-drl-off-indicating` (byte 8 bit 7): shown, 50 becomes D0. Byte 8 is the 80 % daytime light level.
  - `cat-leon-low-beam-always` (byte 21 bit 7): shown, 40 becomes C0.
  - `cat-leon-drl-position` (byte 24) is hidden only because the coding has no byte 24.
- Effect: a tap writes a percentage value that is out of range (208 %, 128 %). The report (sections 1 and 4) says these are held back. The only length check is the test's own filter (`leonMods.test.ts:114-124`), which the app does not apply. The Technical text at customise:640 appears only after opening a row.
- Fix: in `ready`, hide an item when `i.length` is set and differs from `c.length`, at least for `vag-09` (help.ts:276 says nothing stops a different length, so decide the rule and update that note). Make the test call the same predicate as the screen (export it from `items.ts`).
